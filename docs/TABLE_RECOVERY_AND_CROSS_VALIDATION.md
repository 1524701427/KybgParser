# 表格恢复及全字段概算审计（兼容阶段）

预抽取对已有 AST 生成统一恢复视图，不重新读取文件。明确横向、纵向合并和跨度恢复为网格，每个单元格引用原始锚点，不重复计量；多层声明表头拼接。续表要求章节一致、相邻页或明确续表标记、相同表题及兼容重复表头，保留每个片段物理来源。不确定的续表不合并。已有业务原表矩阵不改写。

一次、二次抽取和概算候选进入同一 CandidateRegistry；原有主、次阶段选值优先级保持，尚未将全部旧算子替换为单一 resolver。概算通过恢复视图扫描全部符合章节或明确表题的原表，不限已输出表。复核覆盖已配置/实际字段、条件二次字段以及输出 schema 字段；通用别名匹配只提供待确认候选，明确可信字段规则才判定一致/冲突。单位不明、口径不同、多个候选、同源与缺乏独立来源不自动覆盖。表格采用严格同表题同列逐行审计；未匹配不能说明原值错误。

最终映射算子执行完后，details.json 新增 crossValidation，含所有字段状态、原值/最终值/映射值、表格行审计和候选注册表。result.json、mapped.json 保持原路径及业务语义。审计模式不改数值，不自动补值。复杂无标记合并、无重复表头的通用续表、扫描 PDF、动态多行计量与未迁移领域规则仍需真实样本验证和进一步配置。新增测试 test_table_recovery.py 和 test_cross_validation.py。
